# テストとカバレッジ

CI は PR と main の全変更で動作します。パスによる省略やセルフホストランナーへの切り替えはありません。`required-ci` は API、Web、データ抽出、E2E、Linux 本番イメージの各ジョブがすべて成功した場合だけ成功します。

## 計測する範囲

| レポート | 計測 | 合格基準 |
| --- | --- | --- |
| Go アプリケーション全体 | `go test -race -coverprofile`、API と各コマンド | statements 80%以上 |
| インポーター | 同じ Go プロファイルの対象コマンド | statements 80%以上 |
| Web | Vitest + V8、アプリケーションコード | lines 80%以上 |
| PDF 抽出器 | coverage.py、テストコードを除く scripts | statements 80%以上 |
| 実 MySQL 結合テスト | 結合テストだけの Go 実行範囲 | 実測値を報告 |
| ブラウザー E2E | 実際の画面操作で実行されたソースの範囲 | 実測値を報告 |

単体テストの合算値と結合・E2E 単独の実行範囲は別の指標です。後者の値を単体カバレッジと合算したり、操作が通っただけで100%と見なしたりしません。行カバレッジだけで全分岐の正しさは保証されないため、未認証・状態不一致・他ユーザー・不正パス・失効・障害時のケースもテストします。

Go の実 MySQL テストでは CI 専用の MySQL 8.4 と架空ユーザーを使い、OAuth PKCE、認証が必要な資料・企業情報、ユーザー別ブックマークと名簿番号設定、別端末からの共有、署名付き文書 URL、ログアウトと失効を確認します。本番の認証サービスや実際の配布資料は使いません。

## 会場マップ・利用者設定の確認

- Go の文書テストは URL の有効期間、対象文書との結び付け、署名改変、期限切れ、発行元セッションの失効、認証サービス障害時の拒否、PDF の部分取得を確認します。署名付き URL の取得には閲覧側の Cookie が不要なことも明示してテストします。
- 名簿番号設定は未認証・Origin 不一致・不正な値・資料に割り当てがない値を拒否し、利用者間で値が混ざらず別端末で保持されることを確認します。初期対象は Ec4 で、番号を URL へ保存しません。
- Web のテストは初回番号設定・変更・省略、指定企業表示、初期一覧と専用検索画面、検索条件と保存、URL の直接訪問・再読み込み・戻る・進む、デスクトップのヘッダーとモバイルのナビゲーションを対象にします。OS の外観に合わせたライト・ダークと、案内文の見出し・段落・箇条書きも確認します。
- マップのテストは架空の矩形データでブース選択・午前午後の対応・指定企業と保存企業の表示・企業詳細からの注目位置・資料リンクを確認します。ドラッグ移動、ピンチ・ホイール・キーボードによる拡大縮小、絞り込み後の表示件数と企業一覧、操作後に意図しない企業詳細が開かないことも対象です。座標が不正な領域は操作対象にせず、別フロアにブースを推測して追加しません。
- Python のテストは PDF の矩形変換、OCR 候補の一意な対応、欠落・競合・曖昧な認識の拒否、案内文の構造化を架空データで確認します。単体テストは OCR 呼び出しを模擬し、本物の配布資料を CI へ持ち込みません。元資料を取り込む際の視覚確認は、公開テスト成果物とは分けて行います。

ブラウザー E2E は実際の Go API と MySQL、検証用 OAuth サーバーを通して上記の利用フローを確認します。PDF は `blob:` ではなく API の署名付き URL で開き、内容・ヘッダー・改変拒否・ログアウト後の失効を検証します。企業詳細とマップのクエリは再読み込みと履歴操作でも確認し、名簿番号が URL へ入らないことも検査します。

## PR に表示するレポート

Taskly と同じ方式の bounded JSON レポートと更新型 PR コメントを使います。同一リポジトリの PR は CI の権限を分けた最終ジョブ、fork は既定ブランチの `workflow_run` でコメントします。コメント処理は PR のコードを checkout・実行せず、PR 番号・リポジトリ・現在の head SHA を照合します。実行プロファイルと集計値は Actions artifact に保存し、原本や実データは保存しません。

## ローカルで再現

```sh
go test -race -coverprofile=/tmp/guidance-go.out ./...
go tool cover -func=/tmp/guidance-go.out
go vet ./...
npm --prefix apps/web run typecheck
npm --prefix apps/web run test:coverage
npm --prefix apps/web run build
node --test .github/scripts/coverage-summary.test.mjs deploy/*.test.mjs deploy/r2/*.test.mjs
python3 -m unittest discover -s scripts -p 'test_*.py'
```

実 MySQL テストは使い捨ての専用 DB を用意し、`MYSQL_TEST_DSN` を渡して `go test -race -run '^TestMySQLIntegration$' ./internal/server` を実行します。テストはスキーマを準備し、架空データを書き込みます。稼働データを含む DB の DSN を使わないでください。

ブラウザー E2E は `E2E_MYSQL_PASSWORD` と `E2E_MYSQL_DATABASE` に別の使い捨て DB の接続先を指定し、Chromium をインストールしてから `node scripts/e2e-run.mjs` を実行します。スクリプトが架空データの取り込み、ローカル OAuth サーバー、Go API、Next.js 静的本番ビルドの配信を準備します。詳細な出力先はスクリプトと `apps/web/e2e` を参照してください。
