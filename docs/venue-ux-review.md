# 会場での利用を想定した画面の見直し

評価基準は [Spindle の原則](https://spindle.ameba.design/principles/)。ナビゲーションの配置は [Amebaマンガ](https://dokusho-ojikan.jp/) のデスクトップ・モバイル画面を参照した。配色だけでなく、公式 Spindle UI の入力・選択・通知・リンクを利用する。

## デザイン原則

| 観点 | 見つかった問題 | 対応 |
| --- | --- | --- |
| 敬意を表そう | 来場者には既知の開催日・会場・注意書きや、操作に不要な説明、検索条件が画面を占めていた。 | 最初に企業一覧を表示し、検索条件は専用画面へ移動。開催情報のバナー、宣伝文、各画面の補足文、資料由来の断り書きを削除。名簿番号は利用者が入力し、アカウントから推測しない。 |
| 心を動かそう | 気になる企業・指定企業・地図が分離し、見学先を選んだ結果が分かりにくかった。 | 「気になる」のチェック、指定企業の表示、個人の予定を連動。詳細から地図へ移ると対象ブースを選択表示する。装飾的なコピーではなく、選択に対する具体的な反応を返す。 |
| 快く迎え入れよう | 学科・学年を繰り返し選び、画面状態もURLから復元できなかった。 | 現在の対象を Ec4 に固定し、初回は名簿番号のみ入力する。設定を後回しにでき、後から変更可能。URL・再読み込み・ブラウザーの戻る／進むで画面と企業を復元し、ログイン時にも移動先を引き継ぐ。 |

参照: [デザイン原則](https://spindle.ameba.design/principles/design/)。初回設定モーダルは今回の利用条件に合わせて設計したもので、参照サイトの初回モーダルを再現したものではない。

## アクセシビリティ

- 大きな画面ではヘッダーにメニュー、小さな画面では画面下にアイコンと文字を併記。選択中の画面は `aria-current` でも伝える。
- ナビゲーションと企業詳細は実際のリンクを持ち、新しいタブ、URLのコピー、キーボードでも利用できる。
- リンクと文字ボタンの下線を外し、フォーカスの枠は維持する。複数行の企業名は一覧・詳細・地図の企業一覧を通して左揃えにする。
- 名簿番号の設定とログアウトは、小さなユーザーアイコンから公式SpindleのDropdownMenuで開く。矢印・Home・Endによる項目移動、Escape・Tab・メニュー外の操作による閉じ方とフォーカスを補う。
- モーダルはネイティブの `dialog` を使い、見出し・入力ラベル・エラーを関連付ける。名簿番号を設定しなくても企業検索と地図を使える。
- 地図のブースは企業名を持つボタンにし、選択状態を色・枠・文字で示す。画像上の操作に加え、検索一覧や指定企業から同じ企業へアクセスできる。
- 地図は拡大縮小と表示倍率のリセットを用意。小さなブースを無理に拡大した当たり判定で覆わず、原本の区画に合わせる。
- 地図のドラッグとピンチに加えて、キーボードと拡大縮小ボタンを用意する。絞り込みは必要なときだけ開き、企業名・業種・指定企業・気になる企業で対象を選べる。
- ダークテーマは端末の `prefers-color-scheme` に追従し、Spindle の意味別カラー変数を公式の色プリミティブで切り替える。原本の白い地図は反転させず、文字と区画の読みやすさを保つ。

参照: [アクセシビリティ](https://spindle.ameba.design/principles/accessibility/)。自動テストと画面確認で操作を検証するが、全ての支援技術との互換性や適合認証を主張するものではない。

## パフォーマンス

- `/` を R2 の `index.html` へ内部的に書き換え、初回表示のための外部リダイレクトをなくす。旧 `/index.html` へのアクセスだけを、クエリを保持して `/` へ転送する。
- 認証後の企業情報・保存情報・名簿番号の取得は並列に実行する。
- 地図・PDFは必要になったときに署名付きURLを発行。PDF全体を JavaScript の Blob に読み込まず、ブラウザーで直接表示し、Rangeリクエストにも対応する。
- 地図画像の元の幅・高さを保持して表示領域を確保する。静的アセットはハッシュ付きで長期キャッシュし、私有データ・署名付き資料はキャッシュしない。
- 地図の座標抽出・OCRはインポート時に行い、ブラウザー内では実行しない。

参照: [パフォーマンス](https://spindle.ameba.design/principles/performance/)・[チェックリスト](https://spindle.ameba.design/principles/performance/checklist/)。CIで本番ビルドを検証する。実利用者の Core Web Vitals の数値は、この変更のテストカバレッジとは別の指標であり、未測定の値を報告しない。

## コンテンツ

画面の見出しとメニュー、チェックの表記を「気になる」に揃える。アイコンのみで操作の意味を説明せず、表示ラベルまたはアクセシブルな名前を付ける。エラー時には番号の確認・再試行など次にできる操作を示す。資料本文は見出し・段落・箇条書きに分け、PDFの折り返し改行や不自然な空白を除去する。「配布資料の案内」は独立したページにし、スケジュールとユーザーメニューから移動できる。同じアカウントでの再表示など、操作に不要な自明の説明は画面へ加えない。

参照: [コンテンツ](https://spindle.ameba.design/principles/contents/)・[UIラベリング](https://spindle.ameba.design/principles/contents/ui-labeling/)。

## 検証とデータ境界

単体テストはURL復元・入力・保存・地図選択・署名付きURL・失効を確認する。結合テストは実MySQLで利用者別の保存と再取得を確認し、E2Eは静的ビルド・Go・MySQL・テスト用認証を通した操作を確認する。実施結果とカバレッジはPRのActionsに掲載する。

ローカルでは本番用の静的ビルドに架空API応答を接続し、1440×900・390×844・320×700の各画面幅とライト／ダークで、一覧・検索・マップ・「気になる」・スケジュール・資料案内・企業詳細の計42画面と、開いたユーザーメニュー6通りを確認した。axeのWCAG 2 A／AA・2.1 AAの自動検査で指摘なし、横はみ出し・ブラウザー実行エラーなし。初期一覧の最初の企業カードは全サイズでスクロール前に表示された。

1024・1100・1280pxの幅でもライト／ダーク各3通りを追加確認した。従来の中間幅だけ2段に分かれるヘッダーを1段へ揃え、タイトルの中心のずれは1px未満、ヘッダー内の要素の重なり・横はみ出しなし。これらの画面と開いたユーザーメニューのaxe検査も指摘なしだった。この検査は実認証・DBの検証や、支援技術を利用した手動検査を代替しない。

会場の区画は入力PDFの矩形から抽出し、番号の認識結果が一意に決まらない場合は取り込みを停止する。実資料と区画を重ねた画像で別途照合する。企業情報・学生の指定企業・地図・座標・実資料のスクリーンショットはGitや公開のテスト成果物へ含めず、テストには架空データを使う。
