# Tasklyのやること連携

`TASKLY_API_ORIGIN` と `TASKLY_GUIDANCE_EVENT_ID` を両方設定します。Taskly側には同じイベント識別子と、論理キーから既存課題IDへの対応を非公開設定として登録します。登録手順は [Tasklyの連携運用](https://github.com/asari194617/taskly/blob/main/docs/nnct-corp-guidance-development.md) を参照してください。課題の作成は管理者の明示的な準備操作で行い、ホームの表示・ログインでは作成しません。実ID・対応表・資料中のURL・割り当てはGitに含めません。

ホームは指定ブースの見学、各タームの見学アンケート、全体アンケート、提出用見学シートを表示します。アンケートのURL・期限、提出資料の文書IDとPDFページは、抽出器が追加する `event.task_actions` を実行時に読みます。紙面のページ番号とPDFファイル内のページ番号は区別します。資料本体の取得には引き続き非公開R2の署名付きURLを使います。

完了状態の保存先はTasklyの既存課題完了テーブルだけです。ガイダンスのログインで確認したトークンをサーバー間で使い、本人に許可された課題だけを取得・更新します。画面に戻ったときと表示中30秒ごとに再取得し、未完了への取り消しも共有します。リンクを開いただけでは回答済み・提出済みにしません。連携が利用できない場合は再試行を表示し、ローカルだけの完了状態には切り替えません。

見学アンケートと同じタームの指定企業の自動完了、ガイダンスからの連動解除、手動チェックを保持する由来情報の扱いは、現行の [結合・E2E検証](testing.md) と [Taskly側の構築・更新手順](https://github.com/asari194617/taskly/blob/main/docs/nnct-corp-guidance-development.md) を参照してください。Taskly標準画面の手動操作は単独の項目を更新します。Taskly側のスキーマ・APIを先に配備してから、対応するガイダンスAPIを配備します。

画面の仕様は [画面と利用者設定](features.md)、通信できない場合の参照範囲は [オフライン参照](offline.md) に記載しています。
